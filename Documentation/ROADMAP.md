# Bonsai World — Roadmap

Lightweight direction only. Themes and priorities — **not** specifications and **not** a governing document.

Detailed implementation belongs in [PRODUCT_BLUEPRINT.md](PRODUCT_BLUEPRINT.md). Philosophy belongs in [BONSAI_CONSTITUTION.md](BONSAI_CONSTITUTION.md).

---

## NOW

- Establish the application shell and navigation across the planned feature modules  
- Define Core foundations for models, services, and application data storage — Blueprint §3 (Phase 1 local library)  
- Make Locations trustworthy for physical places where trees and materials live  
- Deliver a first useful path through Collection and Trees  
- Treat **Workspace Profiles** (Essential / Advanced / Complete) as approved architecture: visibility only — document before implementing Settings → Workspace  

---

## NEXT

- Solidify Trees as the center of individual tree records  
- Strengthen Collection overview without turning it into an editing surface  
- Introduce Tasks for actionable care work  
- Introduce Journal for chronological observations  
- Keep Dashboard calm: orientation and overview only  
- Align sidebar order with Blueprint navigation (Trees early; Propagation when Advanced+)  
- Prepare shell navigation so modules can be shown or hidden by Workspace Profile without touching storage  

---

## LATER

- Projects for structured care and improvement work  
- Calendar for time-based care windows  
- Gallery for visual records  
- Settings for user preferences, including **Settings → Workspace → Workspace Profile**  
- Advanced-tier Propagation surfaces when approved  
- Platform layer extraction for pickers / image decode  

---

## SOMEDAY

- Cloud providers under Core (Blueprint storage Phases 2–4)  
- Deeper connections between Tasks, Calendar, Journal, and Projects without overlapping ownership  
- Complete-tier modules when approved  
- Optional licensing that may *enable* or *recommend* a Workspace Profile — never forking the app or library schema  
- **Economy** — future analysis module for collection financial insight (not accounting). Aggregates Trees, Inventory, Propagation, and future Sales/Purchases; owns no master data; other modules must never depend on it. **Do not implement until** Trees are complete, Reference Data is complete, Inventory exists, and core bonsai workflows are stable. Details: [Idea Parking Lot — Economy](Project/00_Idea_Parking_Lot.md#idea-1--economy-module)  
- **Falo Botanical Icon Library** — custom Genus-mapped botanical icons (and later workflow / system families) for the Falo Design System; Trees use botanical icons as placeholders until a primary image exists. **Do not implement until** Trees are complete, Reference Data is complete, and core modules are stable. Details: [Idea Parking Lot — Botanical Icon Library](Project/00_Idea_Parking_Lot.md#idea-2--falo-botanical-icon-library)
